# 0019 -- `outrig init`

## Goal

Interactive end-to-end setup: writes `~/.outrig/config.toml` (skipping if it exists) and
`.agents/outrig/config.toml`, then chains into `outrig init-container` for the first
container.

## Deliverables

- `src/init/mod.rs::run(force: bool) -> Result<()>` matching `doc/usage/init.md`.
- Two phases:
  - **Global config phase** (skipped if `~/.outrig/config.toml` already exists):
    - Prompt for provider style, name, base-url (default by style), api-key env-var name.
    - Prompt for one model: name, identifier (default suggestion by style+style is "openai" ->
      `gpt-4o-mini`), provider link (default the just-defined provider name).
    - Prompt: "Use this model as default-model? [Y/n]" -- if yes, set `default-model` at top
      level.
    - Render and write `~/.outrig/config.toml` atomically.
  - **Repo config phase**:
    - Prompt for `host-path` (default `.`), `container-path` (default `/workspace`).
    - Prompt for default agent name (default `coding`).
    - Prompt: "Override default-model for this agent? [y/N]" -- if yes, prompt for model name.
    - Prompt for preamble (default `"You are a careful coding assistant."`).
    - Set `default-container` to the agent name (matched up so init-container creates a
      matching container-config).
    - Set `default-agent` to the agent name.
    - Render and write `.agents/outrig/config.toml` atomically.
- Both writes refuse to clobber without `--force`. With `--force`, overwrite atomically.
- After both files are written, call `init::container::run(Some(default_agent_name), force)`
  to scaffold the first container.
- `tests/init_scripted.rs`: drive `init` end-to-end in a tempdir against a scripted stdin
  stream; assert resulting configs parse + validate (using 0005's loader).

## Acceptance

- `cargo test init_scripted` passes (configs parse + validate).
- Manual: from a fresh empty git repo, `outrig init` walks through prompts and produces a
  configuration that subsequent `outrig run` (with `OPENAI_API_KEY` set) launches successfully
  end-to-end.
- Drop the `> TODO: Incomplete` markers on `doc/usage/init.md` and `doc/quickstart.md`.

## Dependencies

- 0005-config-merge-validate
- 0017-prompt-ux
- 0018-init-container

## Notes

- The chain into `init-container` is a function call within the same process -- not
  `Command::new("outrig")` re-exec.
- `--force` propagates to the chained `init-container` call so a complete redo works in one
  invocation.
- Atomic writes via `tempfile::NamedTempFile::persist` so an interrupted prompt never leaves a
  half-written config.
