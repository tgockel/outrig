# 0071 -- `outrig image build` for standalone image projects

## Context

Repo-local image-configs already use `outrig build`; standalone image projects
need an equivalent command that reads project-local `image.toml`, builds the
declared image, and validates that the result is a working OutRig toolset image.

Unlike the original proposal, live validation is not optional by default. A
standalone toolset image is only useful if its declared MCP servers start and
report tools.

## Goal

Add `outrig image build` for standalone image projects, with buildah-backed
builds and default live MCP testing.

## Deliverables

- Add `outrig image build [PROJECT_DIR] [--tag <ref>] [--no-test] [--no-cache]`.
- Read `PROJECT_DIR/image.toml`; default `PROJECT_DIR` to the current directory.
- Resolve `[build].dockerfile` and `[build].context` relative to the project
  directory.
- Build with buildah and tag the image as `[image].ref`, unless `--tag <ref>`
  overrides it for that invocation.
- Preserve short image refs accepted by buildah, including `rust-dev` and
  `rust-dev:0.1.0`.
- Always validate the built image by reading `/etc/outrig/image.toml` from the
  image/container and parsing it with the standalone validator.
- By default, start the image and test every declared MCP server:
  - Initialize the server.
  - Call `tools/list`.
  - Report the number of tools returned per server.
- `--no-test` skips only the live MCP server test; it still validates the
  embedded `image.toml`.
- `--no-cache` forwards to the buildah build path consistently with existing
  repo-local image builds.
- Document command output, failure modes, `--tag`, `--no-test`, and
  `--no-cache` in the same task.

## Acceptance

- Building the project generated by `outrig image init rust-dev` succeeds.
- The command fails if `image.toml` is missing, malformed, or missing required
  standalone fields.
- The command fails if the built image does not contain `/etc/outrig/image.toml`.
- The command fails if any declared MCP server cannot initialize or cannot
  return `tools/list`, unless `--no-test` is set.
- `--tag custom-ref` uses `custom-ref` for the build output without rewriting
  `image.toml`.
- E2E tests cover the generated scaffold, embedded-file validation, live MCP
  test success, and `--no-test`.

## Dependencies

- **Hard: 0069**. Build validation uses the standalone `image.toml` parser and
  embedded image path.
- **Hard: 0070**. The init scaffold is the canonical build fixture and the
  first user-facing input to this command.
