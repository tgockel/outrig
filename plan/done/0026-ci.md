# 0026 -- Continuous integration

## Goal

GitHub Actions that keep Cargo + mdbook green on every push and PR. CI cannot run e2e tests
(no podman, no API keys), so it runs the unit suite and verifies the docs build.

## Deliverables

- `.github/workflows/ci.yml` with two jobs:
  - **`cargo`**: on push and PR. Matrix runs the suite under two feature configurations:
    - default features (no `e2e`, no `mistralrs`).
    - `--features mistralrs` (no `e2e`).
    - Steps for each row: checkout; install Rust stable via `dtolnay/rust-toolchain@stable`;
      cache `~/.cargo/registry` + `~/.cargo/git` + `target/` keyed on `Cargo.lock` and the
      feature row; `cargo fmt --check` (once is enough -- factor into a separate job if the
      matrix duplication is annoying); `cargo clippy --all-targets -- -D warnings`;
      `cargo test`. The `mistralrs` row may pull a heavier dep tree; the cache key keeps it
      separate so the no-feature row stays fast.
  - **`mdbook`**: on push and PR.
    - Steps: checkout; install mdbook + mdbook-mermaid via `cargo install`; cache the cargo
      install dir; `mdbook build`. Fails on any broken-link warning if mdbook flags them.
- `rustfmt.toml` minimal: `edition = "2024"`, `max_width = 100`, `use_field_init_shorthand =
  true`. Anything else only if the codebase actually needs it.
- `clippy.toml` minimal (or absent if defaults are fine).
- README badge: `![CI](https://github.com/tgockel/outrig/actions/workflows/ci.yml/badge.svg)`
  near the top.
- Document the e2e test invocation at the bottom of the README (or in a `CONTRIBUTING.md`):
  `cargo test --features e2e` requires podman, buildah, and an `OPENAI_API_KEY`.

## Acceptance

- A pushed branch turns the CI badge green.
- An intentional clippy violation pushed to a feature branch fails CI; reverting the violation
  passes.
- An intentional doc broken link fails the mdbook job (if mdbook surfaces this warning;
  otherwise add `mdbook test` -- which executes Rust code blocks -- and document we don't have
  any).
- `cargo fmt` on the codebase is a no-op (i.e. code is already formatted).

## Dependencies

- 0001-cargo-skeleton

## Notes

- Don't gate other tasks on this. Tasks 0002-0025 should be writeable without CI in place;
  CI just verifies them after the fact.
- Caching trims CI time substantially. The `Swatinem/rust-cache@v2` action is a popular,
  battle-tested option.
- Repo URL placeholders use `tgockel/outrig`; if the project ends up under a different owner,
  the badge URL and edit-url-template in `book.toml` follow.

## Decisions

- **Pulled forward of order; landed before 0014.** Task 0026 has only 0001 as a dependency,
  so doing it early gives later tasks (0011-0025) a CI safety net as they land. The
  trade-off: the spec calls for a `--features mistralrs` matrix row, but that feature is
  introduced by 0014 and would have failed immediately. The mistralrs row is deferred to
  0014, which already lists adding it as a deliverable. 0014's "if 0026 hasn't landed"
  caveats were cleaned up in this task to lock in the order.
- **`Swatinem/rust-cache@v2` over hand-rolled `actions/cache`.** The task spec named this
  as the popular option. One action handles registry + git + target caching keyed on
  `Cargo.lock`. The `mdbook` job uses a distinct `prefix-key: v0-mdbook` so its cache
  doesn't collide with the cargo job's.
- **Single matrix row + single fmt step today.** Spec says fmt-check "once is enough --
  factor into a separate job if the matrix duplication is annoying." With one row there is
  no duplication; factoring now would be premature. Task 0014 picks up the factoring as a
  deliverable when it adds the second row.
- **`clippy.toml` not added.** Spec said "minimal (or absent if defaults are fine)" --
  defaults are fine and the current code passes `clippy --all-targets -- -D warnings`
  cleanly. Adding an empty file would be noise.
- **Switched from `mdbook-linkcheck` to `lychee` for link-checking.** The `[output.linkcheck]`
  preprocessor approach was the original choice in this task's plan, but `mdbook-linkcheck
  0.7.7` is incompatible with `mdbook 0.5.x` -- the renderer protocol changed and the
  preprocessor errors with `missing field "sections"`. Last linkcheck release was 2022 and
  there's no maintained fork. `lychee` is actively maintained, runs as a separate CI job
  via `lycheeverse/lychee-action@v2`, and `--offline` matches the original intent
  (`follow-web-links = false`) -- only intra-doc links fail the build, no flaky external
  HTTP. Acceptance ("intentional broken doc link fails CI") is preserved.
- **`CONTRIBUTING.md` instead of bottom-of-README.** Spec allowed either; chose
  `CONTRIBUTING.md` to keep the README pitch-focused and let contributor docs grow without
  inflating the top-level file.
- **`cargo install --locked`.** Pinning via `--locked` makes the `cargo install` step
  deterministic against the binary crate's `Cargo.lock`. Without it, cache invalidation
  rebuilds at each transitive dep's MAJOR.MINOR drift.
